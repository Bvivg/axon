# Локальный backup/restore Axon

Скрипт [backup-restore.sh](../core/deploy/backup-restore.sh) сохраняет одну БД Postgres через `pg_dump -Fc` и текущие объекты MinIO из `chat-attachments` и `avatars`. Копирование идёт между S3-хранилищами, поэтому в выборке можно сверить метаданные, нужные для отдачи медиа. Архив MinIO содержит данные временного изолированного хранилища. При распаковке используется такая же версия MinIO, как при создании архива.

Нужны Docker Compose, `jq`, OpenSSL, свободный диск, доступ к исходным контейнерам Postgres/MinIO и действующий `core/deploy/.env`. Другой файл передаётся через `AXON_ENV_FILE`. Bundle содержит приватные данные, пишется в новый каталог за пределами репозитория с `umask 077`. Храните и переносите его в зашифрованном хранилище. Перед восстановлением убедитесь, что источник архива доверенный.

1. Остановите запись и дождитесь завершения запросов, включая прямые записи в Postgres/MinIO и фоновые задачи. На локальном Axon остановите Auth, Chat и Game через ту же Compose-конфигурацию, с которой поднят стенд. Оставьте Postgres и MinIO запущенными.
2. Из корня репозитория выполните:
   ```sh
   backup_parent=$(mktemp -d /tmp/axon-backup.XXXXXX)
   core/deploy/backup-restore.sh backup "$backup_parent/snapshot" axon
   ```
   Успешная копия содержит `postgres.dump`, `minio.tar`, счётчики, inventory объектов, контрольные суммы образцов и `SHA256SUMS`. Возобновите запись после завершения команды. При прерывании копирования начните с нового каталога.
3. Восстановите в новом проекте. Скрипт проверяет отсутствие контейнеров, сетей и томов проекта, контрольные суммы архива, затем запускает Postgres и MinIO без публикации наружу:
   ```sh
   core/deploy/backup-restore.sh restore "$backup_parent/snapshot" axon-restore-drill
   ```
4. Убедитесь, что команда завершилась успешно. Она сравнивает `chat.messages` и `chat.files`, полный список ключей и размеров двух бакетов, SHA-256 до трёх объектов каждого бакета и заголовки медиа для той же выборки. Для восстановленной копии выставляются штатные bucket policy. Сервисы хранилища остаются доступны только внутри сети проекта.
5. После проверки удалите только восстановительный проект, если копия больше не нужна:
   ```sh
   docker compose -p axon-restore-drill -f core/deploy/docker-compose.backup.yml down -v
   ```

Compose bootstrap восстанавливает роли сервисов из настроек целевого стенда, `pg_restore` применяет объекты и ACL дампа. Для публичного запуска отдельно настройте доступы, ключи подписи, ротацию, внешнее зашифрованное хранение и регламент отключения входящих записей. Redis, Kafka, активные multipart uploads, история версий объектов, IAM MinIO и внешние провайдеры в этот сценарий не входят.

Локальная репетиция 15 ноября 2026 года: **14 с** на backup и **12 с** на restore. Дамп Postgres — **1 129 032 байта**, архив MinIO — **349 669 376 байт** (около 335 МиБ суммарно). До и после совпали **3 443 сообщения, 23 строки файлов, 20 объектов аватаров и 69 вложений**. Проверены SHA-256 и заголовки трёх объектов из каждого бакета, доступ роли `chat_service` и отказ при попытке восстановиться поверх существующего проекта. Это замеры локального Compose с уже загруженными образами и проверкой данных. Они не задают production RPO/RTO.
