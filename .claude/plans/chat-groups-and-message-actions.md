# Chat — группы, ответ/пересылка, правка/удаление, скрытие чата, чистка загрузок

## Контекст

После медиа (PR #8) в чате остались дыры между бэкендом и вебом и несколько
несделанных вещей. Пользователь попросил закрыть их все:

- ответ и пересылка — бэкенд принимает `reply_to_id` / `forwarded_from_id`,
  но веб их не показывает и не отправляет; для цитаты и «Переслано от» клиенту
  не хватает данных (цель ответа может быть не загружена, исходник пересылки —
  в чужой комнате);
- скрытие чата (`HideRoom`) — только на бэкенде;
- группы — сейчас есть только «открытые» комнаты со входом по ID, а это
  пользователь запретил: чаты начинаются только через контакты. Нужны группы,
  куда людей добавляют из контактов;
- правка и удаление сообщений — нет нигде;
- неотправленные загрузки навсегда остаются в MinIO и `chat.uploads`.

Результат: в вебе можно ответить, переслать, изменить и удалить своё
сообщение, скрыть чат, создать группу из контактов и управлять ей; мусор в
MinIO вычищается сам.

## Решения

### Группы — новый вид комнаты `group`

- Миграция `000005`: `rooms.kind` допускает `group`; `room_members.role`
  (`owner` | `member`, по умолчанию `member`).
- Контракт (additive): `ROOM_KIND_GROUP = 3`, `MemberRole`, `Member.role`,
  RPC `CreateGroup(name, member_user_ids)`, `AddGroupMembers(room_id, user_ids)`,
  `RemoveGroupMember(room_id, user_id)`, `RenameGroup(room_id, name)`.
  `CreateRoom`/`JoinRoom` остаются для старых открытых комнат; в группу по ID
  войти нельзя (`JoinRoom` → `failed_precondition`, как для direct).
- Права: добавлять, удалять и переименовывать может только владелец; выйти
  (`LeaveRoom`) может любой. Уходит владелец — владельцем становится самый
  ранний из оставшихся участников. До 100 участников.
- Добавляемые пользователи проверяются в auth (`GetUsersPublicProfiles` с
  токеном вызывающего): несуществующий ID — ошибка, а не «призрак» в группе.
  Оттуда же берутся имена для `room_members.display_name`.
- Каждое изменение — системное сообщение (`group_created`, `member_added`,
  `member_removed`, `member_left`, `group_renamed`; новое имя — в `body`),
  разосланное как обычное сообщение комнаты.
- Добавленным — сигнал `room_added`; удалённому или вышедшему — новый
  пользовательский сигнал `room_removed`, по которому WS-сессия отписывается
  от комнаты (подписки под мьютексом), а веб убирает чат из списка.

### Ответ и пересылка — данные для отображения приходят с сообщением

- `Message.reply_to` (`ReplyPreview`: id, автор, вид, первые 140 символов
  текста, `deleted`) — собирается JOIN'ом при чтении и из уже найденной цели
  при отправке. Клиенту не нужно искать цель в загруженной истории.
- `messages.forward_origin_author_id` + `Message.forwarded_from_author_id`:
  автор оригинала сохраняется при пересылке (при пересылке пересланного —
  исходный автор, а не промежуточный).

### Правка и удаление — «для всех», только своё

- `messages.edited_at`, `messages.deleted_at`; проверка тела текста
  не действует для удалённых.
- WS: входящие `edit {message_id, body}` и `delete {message_id}`, исходящий
  `message_updated {message}`. Править можно свой текст и подпись к фото,
  видео и файлу; пересланное, голосовое и системное — нельзя. Удаление
  очищает `body` и `payload`, вид остаётся.
- Fan-out: шина доставляет `Delivery{Message, Update}`; обновления проходят
  мимо проверки `seq` (у них старый номер).
- Удалённые исключаются из выборки по `kinds` («Media»), в истории остаются
  заглушкой «Message deleted».
- Kafka для правок и удалений не публикуется — потребителей нет.

### Скрытие чата

Веб: меню в шапке чата — «Delete chat» (скрыть и очистить историю у себя,
`HideRoom`) для личных, «Leave group» для групп; оба с подтверждением.

### Чистка загрузок

- `messages.upload_id` (FK на `uploads`, `ON DELETE SET NULL`) проставляется
  при отправке и копируется при пересылке; миграция заполняет его для уже
  отправленных медиа по совпадению URL.
- Уборщик в chat-сервисе раз в `ATTACHMENTS_SWEEP_INTERVAL` (1 ч) берёт
  загрузки старше `ATTACHMENTS_ORPHAN_AFTER` (24 ч), на которые не ссылается ни
  одно неудалённое сообщение (`FOR UPDATE SKIP LOCKED`, пачками), удаляет их
  объекты из MinIO (ключи — из URL в payload, только с префиксом своего
  бакета) и строки. Так уходят и неотправленные, и удалённые для всех.

### Веб

- Меню сообщения (кнопка «⋯» при наведении и правый клик): Reply, Forward,
  Copy text, Edit, Delete. Ответ — полоса над полем ввода с отменой; цитата в
  пузыре, клик прокручивает к оригиналу. Пересылка — диалог со списком чатов.
  Правка — поле ввода переходит в режим правки. Удаление — подтверждение.
- Группы: в New chat — «New group» (поиск контактов, выбранные чипами,
  название); шапка группы — участники и «Group info» (участники, владелец,
  добавить/удалить/переименовать для владельца, выйти).
- Системные сообщения — строкой по центру.

### Расхождения, найденные по ходу

- Пересылка раньше брала текст и вид от клиента, а подпись «Forwarded from»
  указывает на автора оригинала — так можно было приписать ему чужие слова.
  Теперь пересылка всегда копирует вид, текст и payload источника; клиентский
  `body` игнорируется, `upload_id` вместе с пересылкой — ошибка валидации.
- После «Delete chat» новое сообщение собеседника не возвращало чат (снималось
  скрытие только у отправителя). Теперь любое новое сообщение снимает скрытие
  со всех, кто скрыл чат (история до скрытия остаётся очищенной), и им уходит
  `room_added`.
- Шапка группы и состав обновляются по приходу системного сообщения
  (перезапрос `GetRoom`), отдельного сигнала для этого не заводили.
- По итогам ревью:
  - лимит в 100 участников проверяется в одной транзакции с добавлением
    (строка комнаты блокируется, уже состоящие не считаются);
  - повторный `LeaveRoom` для не-участника — успех, а не ошибка;
  - уборщик удаляет объекты по одной загрузке: неудачные остаются до
    следующего прохода и не блокируют остальные, пачка откатывается только
    если не удалось ничего (MinIO недоступен); на удаление — таймаут;
  - откат миграции удаляет группы, а не превращает их в открытые комнаты
    (иначе в них можно было бы войти по ID);
  - после переподключения веб перезапрашивает историю и превью: правки и
    удаления за время обрыва через `since` не приходят;
  - правка и удаление обновляют и цитаты в ответах на это сообщение.
- По итогам второго ревью:
  - добавленный в группу видит историю только с момента добавления
    (`cleared_through_seq` = последний `seq`), в том числе возвращённый после
    удаления — написанное без него он не читает;
  - добавление нескольких людей — одно системное сообщение `member_added` с
    `target_ids` (additive-поле `SystemPayload.target_ids`), старые события с
    `target_id` читаются как раньше;
  - уборщик снова удаляет объекты одним пакетным `RemoveObjects`, а неудачи
    разбирает по ключам;
  - откат миграции удаляет группы, их загрузки остаются в `uploads` и
    вычищаются уборщиком после повторного применения `000005`;
  - правка в вебе закрывается только после `message_updated` от сервера, при
    ошибке текст остаётся в поле; незаконченный черновик возвращается после
    выхода из правки;
  - при обрыве связи неподтверждённые пересылки и правки сообщают об этом;
    после переподключения перезапрашивается только новейшая страница истории
    и сливается с первой загруженной, старые страницы и место чтения
    остаются; если за обрыв пришло больше страницы — история сбрасывается до
    новейшей, чтобы не было дыры.
- По итогам следующих ревью:
  - правки и удаления по WS не уходят тем, кому сообщение не видно
    (`seq` не больше их `cleared_through_seq`);
  - выход из группы и передача владения — одна транзакция под блокировкой
    строки комнаты; лимит группы считается отдельным запросом уже после
    блокировки, иначе в READ COMMITTED берётся снимок до ожидания;
  - системное сообщение группы пишется после изменения состава как
    best-effort: сбой логируется, а сигналы `room_added`/`room_removed` всё
    равно уходят;
  - если шина недоступна, правка возвращается автору напрямую, чтобы веб не
    ждал подтверждения вечно;
  - уборщик после блокировки строк перепроверяет сирот новым запросом:
    сообщение, отправленное во время выборки, спасает загрузку.

## Как проверяется

- `make check`, `make lint`, eslint/tsc.
- `make test-integration` — роли и владелец при выходе, `reply_to`/автор
  оригинала в выборке, правка/удаление, уборщик удаляет только сирот.
- `make test-e2e` — группа целиком (создание, добавление, удаление,
  переименование, выход, чужой не читает), правка/удаление с живой
  рассылкой, ответ/пересылка.
- `make test-web-e2e` — группа из контактов, ответ с цитатой, пересылка с
  «Forwarded from», правка у собеседника, удаление, скрытие чата.
- Руками на дев-стенде, десктоп и 375px.

## Критерий готовности

Все перечисленные действия доступны в вебе и проверены e2e, в группу нельзя
попасть иначе как через владельца, а неотправленные и удалённые файлы
исчезают из MinIO сами.
