# Chat — альбомы, просмотрщик, плеер (срез 4 переноса из nod)

Общий план: `chat-port-from-nod.md`. Загрузка частями — `chat-media-pipeline.md`.

## Контекст

Несколько фото уходят отдельными сообщениями (по одному на файл), просмотр —
простой диалог на одно фото или видео без листания, зума и скачивания; видео играет
голый `<video>`. В nod — альбомы до 10 вложений, галерея по медиа чата, зум, плеер
с нормальной панелью. Переносим.

Результат: фото и видео, отправленные вместе, — одно сообщение-альбом (до 10) с
сеткой плиток и общей подписью; просмотрщик листает все фото и видео чата,
зумит, качает; видео — плеер media-chrome.

## Решения

### Бэкенд
- Новый вид `album` (`MESSAGE_KIND_ALBUM = 7`, additive). Payload — `{items: [...]}`,
  элемент — `kind` (`image`/`video`) и поля полезной нагрузки этого вида; 2–10 элементов,
  только фото и видео (документы и голос — по одному, как сейчас).
- `message_uploads (message_id, position, upload_id)` — ссылки альбома на загрузки
  (уборщик не должен удалить загрузку, которую показывает альбом). `message_id` →
  `ON DELETE CASCADE`, `upload_id` → `ON DELETE CASCADE`; индекс по `upload_id`.
  Брошенная загрузка — без ссылок из `messages.upload_id` **и** из `message_uploads`
  живых сообщений.
- WS `send` получает `upload_ids` (до 10, additive): одна — как `upload_id`, две и
  больше — альбом в том порядке, в каком пришли; подпись — общая.
- Пересылка альбома копирует payload и ссылки `message_uploads`. Часть альбома:
  `ForwardMessages.parts [{message_id, positions}]` (additive) — одна позиция
  уходит обычным фото/видео, несколько — альбомом из них.
- Правка подписи альбома — как у фото; удаление — как обычно (payload чистится).

### Веб
- Поле ввода: готовые фото и видео уходят альбомами по 10 (подпись — на первом
  альбоме), документы — по одному, как сейчас.
- Плитки альбома: 2 — в ряд, 3 — одна широкая + две, 4 — 2×2, дальше — по три в
  ряд, нечётный хвост растягивается; плитка 140–280 × ≤ 320 px.
- Просмотрщик `yet-another-react-lightbox` (Zoom ×4, Counter, Download, Captions):
  слайды — все фото и видео загруженной ленты (альбомы разворачиваются), открывается
  на нажатом; видео-слайд — плеер, играет только активный; клик по фону закрывает.
- Плеер `media-chrome` + `@player.style/minimal`, только на клиенте (`next/dynamic`
  без SSR: веб-компоненты).
- Выбор сообщений: в альбоме можно отметить отдельные фото (как в nod) — пересылка
  только их; счётчик выбора считает фото.
- Инфо чата: вкладка медиа показывает и элементы альбомов.

## Проверка
- Go unit: валидация альбома (границы 2/10, виды), отправка, частичная пересылка.
- Integration: альбом не даёт уборщику удалить свои загрузки.
- Core e2e: альбом из 3 фото доходит собеседнику по порядку; пересылка двух из трёх.
- Web e2e: 4 фото одним сообщением, просмотрщик листается стрелками, Esc закрывает.
- Живьём: сетки 2/3/4/5, видео в просмотрщике с панелью, 375 px.

## Критерий готовности
Фото, отправленные вместе, приходят одним альбомом, просмотрщик листает медиа чата
с зумом и плеером; тесты зелёные.
