# Web — дизайн-система «Signal»

## Контекст

В `design/` (локально, в git не коммитится) лежит экспорт макетов Axon: токены,
компоненты, десктопный шелл, авторизация и профиль, состояния чата, экраны
загрузки/пустоты/ошибок, а также игры, звонки и нативные экраны. Веб-клиент
сейчас собран на дефолтной shadcn-палитре (синий primary, системный шрифт,
иконочный rail на 80px, плавающий pill-навбар на мобиле), и визуально с
макетами не совпадает ни в одном экране.

Результат этапа: `ui/web` выглядит и ведёт себя как «Signal» во всех
экранах, у которых есть бэкенд — шелл, авторизация, профиль, чат, состояния
загрузки/пустоты/ошибок, в светлой и тёмной теме.

Вне этапа: игры, звонки и нативные экраны (бэкенда нет), а также rich-сообщения
в вебе (ответы, пересылка, вложения, голос). Бэкенд их уже умеет, но это новая
функциональность клиента, а не перенос дизайна — отдельный этап.

## Решения

### Токены — `light-dark()` поверх одного набора переменных

Палитра из макетов (OKLCH, hue 90, монохром + `--signal` как живой/фокусный цвет)
задаётся один раз в `@theme` через `light-dark(светлое, тёмное)`, а тема
переключается `color-scheme`: по умолчанию `light dark` (системная),
`[data-theme]` на `<html>` фиксирует светлую или тёмную. Так нет трёх копий
палитры (светлая, тёмная по медиазапросу, тёмная по атрибуту), а превью темы
в настройках рисуется тем же набором токенов через локальный `color-scheme`.
Тени собраны из слоёв с `light-dark()`-цветами, так что и `--shadow-overlay`
задаётся один раз. Tailwind (Lightning CSS) полифилит `light-dark()` через
`--lightningcss-light/dark`, поэтому токены вычисляются на `:root`: локальный
`color-scheme` на поддереве тему не меняет, и превью тем в Appearance
нарисованы литеральными цветами.

Tailwind-имена сохраняются shadcn-овскими (`background`, `primary`, `muted`,
`accent`, `border`, `input`, `ring`, `sidebar`, `popover`), добавляются `signal`,
`success`, `warning`, `scrim`. Скругления совпадают со шкалой Tailwind по
умолчанию (`md` 6, `lg` 8, `xl` 12), поэтому шкала не переопределяется.

### Шрифты — Geist через `next/font/google`

Geist и Geist Mono, веса 400/500/600. `next/font` отдаёт их с того же origin,
без отдельной зависимости. Базовый кегль 14/20, `eyebrow` (mono 11, +0.06em,
uppercase) и `Kbd` — общие утилиты.

### Движение

Одна кривая `cubic-bezier(0.2, 0, 0, 1)`, 120 мс для hover, 200 мс для
появления оверлеев (fade + подъём на 4px). `prefers-reduced-motion` глушит всё.

### Шелл

- ≥ lg: сайдбар 248px — бренд, навигация (Lobby, Chats со счётчиком
  непрочитанных, Calls), «Recent» — последние чаты с непрочитанными и
  онлайн-точкой, внизу аккаунт с меню (профиль, сессии, тема, выход).
- ≥ md: топбар 52px — хлебные крошки, «Search or jump to… ⌘K», статус
  соединения, переключатель темы.
- < lg: прежняя плавающая нижняя навигация (Games, Calls, Chats, Profile) и
  круглая кнопка поиска, которая теперь открывает ⌘K. Таббар из макета
  отвергнут: прежний вариант понравился больше.
- ⌘K — командная палитра: комнаты и люди (поиск через `SearchUsers`), переходы,
  новая комната, тема, выход. `G L` / `G C` — переходы с клавиатуры.
- Статус соединения — по presence-сокету и `navigator.onLine`: Connected,
  Reconnecting…, Offline.

### Авторизация и профиль

- Вход/регистрация: OAuth-кнопки сверху, форма ниже, ошибка — у поля
  («Email or password is incorrect.»), лимит попыток — предупреждающая карточка,
  отправка — спиннер в кнопке. Показ пароля. Описаний под заголовками нет
  (`rules/nextjs-web.md`).
- OAuth callback: провайдер ··· Axon с индикатором, ошибки с кодом.
- Профиль: секции с eyebrow-заголовками вместо карточек, «Appearance» — выбор
  темы превью-карточками.

### Чат

Список чатов, переписка (пузыри) и диалог «New chat» остаются в прежнем
дизайне — вариант из макета попробовали и откатили, прежний понравился больше.
Меняются только акценты: синий берётся из `signal`, потому что `primary`
теперь монохромный. Сокет активности комнат переехал в шелл
(`ChatActivityProvider`), чтобы счётчик непрочитанных в сайдбаре жил на любой
странице; список берёт «печатает» из него.

«New chat» — только поиск контактов (точное совпадение по email или display
name): выбрал человека, первое сообщение создаёт direct-комнату. Вкладки
«Group» и «Join by ID» и поиск по id комнаты и имени группы убраны из UI — они
были нужны только e2e-набору, который теперь идёт тем же путём, что и человек.
RPC `CreateRoom`/`JoinRoom` на бэкенде остаются.

### Загрузка, пустота, ошибки

`Skeleton`, `LoadingDots`, `ErrorCard` (код Connect + «Try again»),
`EmptyState`. Страницы `not-found` (404) и `error` (500). Заглушки Lobby и
Calls — пустые состояния.

## Как проверяется

- `make web-check` — eslint, tsc, `next build` без ошибок.
- `make test-web-e2e` — весь Playwright-набор зелёный.
- Руками в браузере (дев-стек, http://localhost:3003), светлая и тёмная тема,
  ширина 1440 и 390: вход с неверным паролем, регистрация, OAuth через fake
  provider, профиль и сессии, ⌘K, переход `G C`, чат двух пользователей
  (typing, ✓✓, онлайн), остановленный gateway — баннер переподключения,
  несуществующий адрес — 404.

## Критерий готовности

Каждый экран веба с живым бэкендом совпадает с макетом «Signal» по токенам,
типографике и раскладке в обеих темах на десктопе и мобиле, а `make web-check`
и `make test-web-e2e` проходят.
