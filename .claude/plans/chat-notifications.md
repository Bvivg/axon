# Chat — уведомления: тосты, Web Push, счётчик во вкладке (срез 5 переноса из nod)

Общий план: `chat-port-from-nod.md`.

## Контекст

О новом сообщении в другом чате сейчас говорит только бейдж в списке; закрыта
вкладка — человек не узнает ничего. В nod: тост, если окно открыто, Web Push, если
нет, счётчик непрочитанных в заголовке вкладки. Переносим.

Результат: сообщение в другой чат при открытом приложении — тост с автором и
текстом (клик открывает чат); приложение не видно ни в одной вкладке — системное
уведомление Web Push; в заголовке вкладки — число непрочитанных.

## Решения

### Кто что решает
- Тост решает клиент: сокет активности уже получает сообщения всех чатов. Тост —
  если автор не я и этот чат не открыт или окно не на виду (`useAttention`).
- Push решает сервер, потому что push нужно показать всегда, если он пришёл
  (`userVisibleOnly`): получатель «виден», если хоть одна его вкладка видна — тогда
  тост покажет клиент, push не нужен. Не виден — push на все его подписки.
- Видимость приходит по сокету присутствия: клиент шлёт `{"type":"visibility",
  "visible":bool}`; трекер держит в Redis множество видимых соединений пользователя
  (`presence:visible:<user>`, срок как у присутствия), снимает при скрытии и закрытии.

### Бэкенд
- Миграция `000009_push_subscriptions`: `push_subscriptions (endpoint PK, user_id,
  p256dh, auth, created_at)`, индекс по `user_id`.
- RPC: `GetPushKey` (публичный VAPID-ключ; пусто — push выключен),
  `SubscribePush(endpoint, p256dh, auth)` (повтор перепривязывает endpoint к
  вызывающему), `UnsubscribePush(endpoint)`. Gateway: policy + proxy.
- Отправка — после фиксации сообщения, вне запроса, не блокирует `send`:
  получатели — участники комнаты кроме автора, системные сообщения не шлются.
  Заголовок — имя автора (личка) или название группы; текст — превью (группа:
  «Автор: текст»); `url` — чат; `tag` — комната (новое сообщение заменяет старое
  уведомление того же чата). Ответ 404/410 — подписка удаляется.
- `webpush-go` v1.4.0 (RFC 8030/8291/8292, протокол стабилен). Ключи — `make
  vapid-key` пишет `CHAT_VAPID_PUBLIC_KEY`/`CHAT_VAPID_PRIVATE_KEY` в
  `core/deploy/.env`; без ключей push выключен, остальное работает.

### Веб
- `public/sw.js`: `push` → `showNotification`, `notificationclick` → фокус
  открытой вкладки и переход в чат, иначе новая вкладка.
- Профиль → «Notifications»: включить (разрешение браузера → подписка → RPC) /
  выключить; состояние — из `PushManager.getSubscription()`.
- Тосты — `sonner` из среза 2, клик открывает чат.
- Заголовок вкладки — `(N) Axon`, N — сумма непрочитанных по списку чатов.

## Расхождения с замыслом
- Настройка — отдельная страница профиля `/profile/notifications`, а не блок в
  общем профиле: так она стоит рядом с Sessions/Appearance.
- При загрузке приложения существующая подписка пересылается на сервер
  (`resyncPush`): браузер мог сменить endpoint, сервер мог её удалить по 410.
- Выход из аккаунта сначала снимает подписку (`disablePush`), иначе на этом
  устройстве продолжат приходить push чужого аккаунта.
- E2E получает VAPID-ключ через `make e2e-key` (`.env.e2e`). Доставка в e2e не
  проверяется: endpoint обязан быть https, push-сервис браузера в контейнере
  недоступен — её покрывают unit-тесты (шифрование, 404/410, выбор получателей).
- Тост не показывается в открытом чате даже при простое (он исчезнет раньше, чем
  человек вернётся) и при скрытой вкладке (тогда — push). Счётчик во вкладке
  учитывает простой: чат, открытый без активности больше 15 с,
  не отмечается прочитанным (срез 1), поэтому его сообщения тоже считаются.

## Проверка
- Go unit: решение «push или нет» (видим / не видим / автор / системное), 410 удаляет подписку.
- Integration: видимые соединения в Redis с истечением; подписки.
- Core e2e (`make test-e2e`, `e2e/push_test.go`): ключ — несжатая точка P-256,
  http-endpoint и подписка без `auth` → `invalid_argument`, повторная подписка и
  отписка идемпотентны, аноним → `unauthenticated`.
- Web e2e (`e2e/notifications.spec.ts`): тост о сообщении из другого чата, в
  открытом — нет, клик «Open» ведёт в чат; `(N) Axon`; страница профиля предлагает
  «Turn on», когда у сервера есть ключ.
- Живьём: тосты и счётчик — Playwright; push — в Chrome пользователя после
  `make vapid-key` (разрешение даёт он).

## Критерий готовности
Сообщение в другой чат даёт тост, при скрытом приложении — системное уведомление,
непрочитанное видно в заголовке вкладки; тесты зелёные.
