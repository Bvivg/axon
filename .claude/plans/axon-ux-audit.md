# AXON. Аудит UX всего веб-интерфейса

13 ноября 2026. Аудит актуального AXON на Docker-стенде. В рабочем дереве доступен веб-клиент. SwiftUI-клиента в `ui/` нет. В область вошли вход и регистрация, навигация и поиск, чаты, звонки, игры, профиль, уведомления, админка и страницы ошибок.

## Правила показа

- Подтверждение результата задачи остаётся там, где его ищут. Победа и окончание развёрнутого звонка получают крупный блок. Сохранение профиля подтверждается рядом с формой. Короткий toast сообщает о событии из другого контекста. [Apple HIG](https://developer.apple.com/design/human-interface-guidelines/feedback) · [Carbon](https://www.carbondesignsystem.com/building-blocks/core/patterns/notifications)
- Диалог для входящего звонка принимает фокус. После завершения фокус возвращается к осмысленному элементу исходного экрана. Остальные уведомления не сдвигают фокус. Для информационных обновлений использовать `role=status`, для важных ошибок `role=alert`. История и непрочитанные сохраняют события после закрытия toast. [W3C Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) · [W3C Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
- Первая строка говорит, что произошло. Вторая добавляет только нужный контекст. По возможности одно действие с конкретным глаголом. Цвет сопровождается текстом или иконкой. Ошибки полей связываются через `aria-describedby`. [GOV.UK Error Message](https://design-system.service.gov.uk/components/error-message/) · [Carbon Notification](https://www.carbondesignsystem.com/building-blocks/core/components/notification/guidelines)
- Короткое движение только при изменении состояния. С `prefers-reduced-motion` статус остаётся читаемым без анимации. Проектная цель для основных кнопок на телефоне — 44 px. Toast и нижняя панель не перекрывают composer, End и текущий фокус. [W3C Motion](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions) · [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) · [W3C Focus](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum)

## Порядок реализации

1. **Доставка событий и восстановление.** Первый DM, подавление повторов, статусы сети и отправки. Тесты на первую переписку, reconnect, отказ отправки, переключение чата и дубль события. Файлы `chat-activity.tsx`, `use-room-activity-socket.ts`, `use-chat-socket.ts`, `chat-room-view.tsx`, `message-composer.tsx`, серверный `ws/handler.go` при необходимости.
2. **Единое отображение.** Расширить существующие Sonner, Alert и Dialog, согласовать места показа и приоритет. Перевести на них исходы звонков, результат игры и уведомление о сообщении. Файлы `ui/sonner.tsx`, `ui/alert.tsx`, `calls/call-prompt.tsx`, `calls/call-overlay.tsx`, `calls/call-mini-bar.tsx`, `games/tictactoe/match.tsx`. Тесты на навигацию, параллельный toast и входящий, End в обеих раскладках, повтор подключения и переход по истории.
3. **Настройки и навигация.** Профиль, сообщения об ошибках, отзываемые сессии, роли, пустые состояния, обнаружимость поиска. Файлы `components/profile/`, `components/admin/`, `components/auth/`, `components/nav/`, `app/error.tsx`. Тесты на успех и ошибку сохранения, отказ разрешения и отзыв второй тестовой сессии.
4. **Приёмка.** Docker-прогон на 320×568, 390×844, 844×390 и 1440×900, светлая и тёмная темы, длинные имена, клавиатура, reduced motion. Отдельный прогон на физическом Safari для входящего и уведомлений. Результаты фиксировать отдельно для каждого сценария.

Сохраняем текущие компоненты, истории Calls и Games и существующие маршруты. Отдельный центр событий имеет смысл только если этих мест окажется недостаточно.

## Доказательства и границы

После аудита в AXON добавлены первое уведомление о сообщении, прежний ID при повторе неподтверждённой отправки, редактируемый черновик при обрыве, заметные исходы игры и звонка, приоритет входящего, настройки звуков в профиле, подтверждения для сессий и ролей. Поиск сохраняет полученные результаты и показывает, если нужно повторить загрузку чатов или людей. История Tic-Tac-Toe показывает имя соперника и время последнего изменения. `Play again` создаёт новую партию с собственной ссылкой для приглашения.

В Chromium проверены публичные формы, профиль, отзыв второй сессии, сообщения, звонок 1:1, обрыв WS с черновиком и возврат обычного аккаунта из админского маршрута. Изменение ролей просмотрено по коду. Итоговые скриншоты и журналы лежат в `.local/evidence/ux-audit-2026-11-13/`. Часть снимков исходного аудита была удалена при очистке каталога результатов Playwright.

Отдельная индикация восстановления сети, общий пересмотр загрузочных состояний и повтор отправки после закрытия чата остаются открытыми. Физический Safari, групповые звонки, реальный push, полный цикл загрузки вложений, OAuth и экран 500 для этих изменений отдельно не прогонялись.
