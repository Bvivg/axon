# Chat — выбор сообщений, пакетная пересылка, «кто прочитал» (срез 2 переноса из nod)

Общий план: `chat-port-from-nod.md`. Срез 1 — `chat-transcript.md`.

## Контекст

Переслать, скопировать или удалить можно только одно сообщение за раз; пересылка —
в один чат; кто прочитал сообщение в группе — не видно (только общие галочки).
На телефоне ответить можно только через меню. В nod всё это есть — переносим.

Результат: несколько сообщений выбираются (меню «Select», протяжка мышью),
пересылаются в несколько чатов с комментарием, копируются одним текстом,
свои — удаляются пачкой; у своего сообщения видно, кто и когда его прочитал;
свайп влево по сообщению на таче — ответ.

## Решения

### Бэкенд
- Миграция `000006_read_marks`: `read_marks (room_id, user_id, from_seq, to_seq,
  read_at)`, индекс `(room_id, user_id, to_seq)`. `MarkRead` одной командой:
  блокирует строку участника, двигает `last_read_seq` (не дальше последнего
  сообщения комнаты — раньше клиент мог прислать любое число) и пишет диапазон
  `(старый, новый]`, если он не пустой.
- `ListMessageReaders(message_id)` → `[{user_id, read_at?}]`: только автор
  сообщения (чужие прочтения — не его дело), без автора, по `read_at`; прочитавшие
  до миграции — без времени.
- `ForwardMessages(message_ids ≤100, room_ids ≤50, comment, client_id)`: в каждую
  комнату — сначала комментарий, потом копии в порядке запроса (клиент шлёт в порядке
  ленты). Права на все комнаты и исходники проверяются до первой копии. Каждая копия
  — обычный `appendValidated` (права, «пересланное» с исходным автором, тот же
  fan-out), `client_id` копии выводится из `client_id` запроса, комнаты и сообщения —
  повтор запроса не дублирует. Пересылку пересланного оставляем как в axon.
- WS `delete` принимает `message_ids` (≤100) рядом с `message_id`: удаляются только
  свои, по одному fan-out на сообщение.
- gateway: policy + proxy для двух RPC; `ForwardMessages` — в чувствительном тарифе
  лимитера (до 5000 вставок за запрос), `ListMessageReaders` — в обычном.
- RPC-ошибки «не автор» → `PermissionDenied`, «удалено» → `FailedPrecondition`
  (раньше их видел только WS).

### Веб
- Выбор — `Set` id сообщений в `chat-room-view`; войти — пункт меню «Select» или
  протяжка мышью через несколько сообщений (внутри одного — обычное выделение
  текста), у края ленты 48 px — автопрокрутка. Системные и удалённые не выбираются.
  Esc и крестик — выйти.
- Панель выбора поверх поля ввода: «N selected», Copy, Forward, Delete (если все
  выбранные свои). Copy — одно сообщение текстом, несколько — «Имя, время\nтекст»
  через пустую строку.
- Пересылка: диалог с отметками чатов + комментарий; один чат — переход в него,
  несколько — тост «Forwarded to N chats».
- «Read by»: пункт меню у своего сообщения (в личке — «Read at …»), список со временем.
- Свайп влево на таче (`react-swipeable`): начало после 12 px, ответ от 56 px,
  сдвиг не больше 72 px; вертикальное начало — прокрутка; при выделенном тексте
  не срабатывает. Долгое нажатие — меню (у `DropdownMenu` уже есть `onContextMenu`).
- Копирование картинки — через `canvas` в PNG (`ClipboardItem`).
- Тосты — `sonner` (shadcn), понадобятся и в срезе 5.
- Найдено по ходу: каждое входящее сообщение дважды инвалидировало последнее
  сообщение, список чатов и медиа (лента + сокет активности), пачка пересланных
  выбирала лимитер gateway (429). Теперь `lib/query/refresh.ts` склеивает обновления
  одного ключа в окне 600 мс.
- Панель выбора лежит поверх поля ввода, а не вместо него: черновик не теряется.

## Проверка
- Go: unit (`service`), integration (`read_marks`, forward batch, лимиты, права), core e2e.
- vitest: `selection`, `drag-select` (диапазон), копирование текста.
- `ui/web/e2e/selection.spec.ts`: выбрать 3 → переслать в 2 чата с комментарием,
  у получателей — комментарий и 3 пересланных по порядку; «Read by» в группе;
  пакетное удаление своих.
- Живьём: протяжка мышью с автопрокруткой, свайп на 375 px.

## Критерий готовности
Несколько сообщений пересылаются в несколько чатов одним действием, свои удаляются
пачкой, «Read by» показывает прочитавших; e2e зелёные.
