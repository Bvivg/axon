# Go — конвенции сервисов (core/)

## Структура пакетов
- Каждый сервис — отдельный Go-модуль (`go.mod`) внутри `core/services/<name>/`, связка через `go.work`.
- `internal/` — всё, что не должно импортироваться извне сервиса. Между сервисами общаются только через `shared/proto` и `shared/pkg`.
- Не тащить бизнес-логику в `cmd/main.go` — там только wiring (конфиг, DI, старт сервера).

## Ошибки
- Оборачивать ошибки с контекстом: `fmt.Errorf("session: apply move: %w", err)`.
- Доменные ошибки — через sentinel errors или собственные типы (`var ErrWallBlocksPath = errors.New(...)`), никаких голых строк для сравнения.
- На границе gRPC/Connect конвертировать доменные ошибки в `connect.Code*` явно, не пробрасывать голый `error` наружу.

## Конкурентность
- Explicit `context.Context` первым параметром везде, где может быть отмена/таймаут.
- Никаких глобальных мьютабельных singletons для session state — состояние сессии живёт в `session.Manager`, доступ через методы, не через прямой доступ к map.

## Игровой движок (`services/game/internal/engine`)
- Каждая игра реализует единый интерфейс `Game` (`Init/ApplyMove/ValidMoves/IsTerminal`) — никаких дополнительных публичных методов на конкретных играх, если это ломает взаимозаменяемость через `registry.go`.
- Валидация хода — pure function: `ApplyMove(state, move) (State, error)` не должна иметь побочных эффектов (I/O, публикация в Kafka — уровнем выше, в `session`).
- Quoridor: `pathfinding.go` содержит только BFS/graph-логику, без знания о WebSocket/сессиях — тестируется в изоляции.

## Тесты
- Доменная логика игр (`games/*`) — table-driven тесты, без моков, чистые unit-тесты на `ApplyMove`/`ValidMoves`.
- `session`/`server` — тесты через интерфейсы (моки на repository/publisher), не поднимать реальный Postgres/Kafka в unit-тестах.

## Линтеры / форматирование
- `gofmt` + `golangci-lint` обязательны перед коммитом.
- Комментарии, включая doc-комментарии на экспортируемых идентификаторах — см. `rules/comments.md`. Единственное исключение для Go — директивы (`//go:build`, `//go:generate`, `//go:embed`, `// +build`, `//nolint:...`), они не документация и линтер/компилятор их разбирает.
