# Security / Secrets

## Секреты
- Реальные секреты — никогда в репозитории. `.env.example` с плейсхолдерами коммитится, `.env`/`.env.local` — в `.gitignore`.
- Локально/Docker-compose — секреты через `.env` файл, подключаемый в `docker-compose.yml`.
- CI — только через secrets-хранилище платформы (GitHub Actions secrets), не хардкодить в workflow-файлах.
- Ротация JWT-ключей (RS256) — предусмотреть с самого начала JWKS-эндпоинт с несколькими активными ключами (`kid`), не завязываться на единственный статичный ключ.

## Gateway — граница доверия
- Вся входная валидация (форматы, лимиты длины, санитизация) — на gateway, downstream-сервисы не должны доверять входу от других сервисов без проверки, но не обязаны заново валидировать то, что уже провалидировал gateway на границе с внешним клиентом.
- Rate limiting — на gateway, по `user_id`/IP, отдельные лимиты на дорогие операции (создание игровой сессии, звонок) vs дешёвые (получение состояния).
- CORS — на web-клиент только с явного allow-list origin, не `*`.

## Аутентификация/авторизация
- JWT verification — локально на каждом сервисе через JWKS (уже заложено), не дергать auth-сервис на каждый запрос.
- Авторизация уровня ресурса (может ли этот игрок ходить в этой сессии) — проверяется в самом `game`/`chat`/`calling` сервисе, не только на gateway.

## Health checks (см. также rules/observability.md)
- `/healthz`/`/readyz` — обязательны на каждом сервисе с первого дня, это же используется docker-compose healthcheck и в CI при поднятии e2e-стека (ждать `service_healthy` перед прогоном тестов).
