# MCP-инструменты

## Доступные серверы (`.mcp.json`)
- **shadcn** — поиск/примеры/установка компонентов shadcn для `ui/web`.
- **postgres** — read-only SQL к локальной БД (`localhost:55432`, дев-креды),
  видит все схемы (`auth`/`chat`/`game`/`calling`) в одной базе.
- **docker** — список/логи/inspect/start/stop/restart контейнеров на локальном
  Docker-демоне.
- **playwright** — управление настоящим браузером (navigate/click/snapshot/
  screenshot/network) для проверки веб-клиента.
- **github** — репозиторий `Bvivg/axon`: PR, issues, файлы, коммиты, ревью,
  статусы.

## Правило: MCP вместо ручных команд
Когда MCP покрывает нужное действие — использовать его, а не эквивалентную
ручную команду через Bash:

| Задача | Использовать | Не использовать |
|---|---|---|
| Посмотреть/проверить данные в БД | `postgres` (`query`) | `docker compose exec postgres psql ...` |
| Статус/логи/рестарт контейнера | `docker` (`docker_container_*`) | `docker ps` / `docker logs` / `docker compose ps` руками |
| Проверить веб-функциональность в браузере | `playwright` | ручной `curl`, если нужен именно рендер/интерактивность |
| PR/issue/файлы GitHub | `github` | `gh` CLI через Bash |

**Почему**: структурированный вывод MCP не нужно парсить из текста терминала,
и это меньше токенов на то же самое действие.

## Исключения — где ручные команды остаются
- `git` (commit/push/branch/merge) и любые локальные операции с рабочим
  деревом — только через Bash, `github`-MCP не имеет доступа к локальному
  git и не должен использоваться для коммитов.
- Оркестрация `docker compose` целиком (`up`/`down`/`build` по всему стеку,
  миграции) — через Bash по `rules/infra.md`; `docker`-MCP управляет только
  уже существующими контейнерами, не compose-файлами.
- Действия, которых у MCP нет вовсе (например `buf generate`, `go test`) —
  как и раньше, через Bash/Docker.

## Поддержка актуальности
При добавлении или удалении MCP-сервера в `.mcp.json` — тем же изменением
обновляются обе таблицы выше («Доступные серверы» и «MCP вместо ручных
команд»). Это единственное место в репозитории, где видно, какие MCP есть
в проекте и зачем — сервер, добавленный в `.mcp.json`, но не описанный
здесь, для остальных участников не существует.
