# Тестирование (весь стек)

## Уровни тестов
1. **Unit** — чистая доменная логика без внешних зависимостей (игровые движки, валидация, парсинг). Без Docker, без моков I/O.
2. **Integration** — сервис + реальная БД/Kafka/Redis, но в изоляции от остальных сервисов. Через `docker compose run`, с тестовым окружением (`docker-compose.test.yml` или testcontainers-go).
3. **E2E** — весь стек поднят через Docker-compose (gateway + все сервисы + Postgres/Redis/Kafka/LiveKit), тест идёт через реальный клиентский путь (HTTP/Connect/WebSocket), как если бы это делал настоящий клиент.

## Правило: E2E-тест обязателен на каждую крупную фичу
"Крупная фича" = новый флоу, доступный конечному пользователю (не рефакторинг, не внутренний рефактор пакета). Примеры, что требует e2e:
- Регистрация / логин / OAuth-флоу целиком (клиент → auth → JWT выдан → gateway принимает токен)
- Партия в игру от создания сессии до победы/ничьи для **каждой игры отдельно** (включая Quoridor — полный сценарий с несколькими стенами)
- Отправка/получение сообщения в чате между двумя участниками
- Установка звонка: создание комнаты → выдача токена → участник подключился (можно мокать сам LiveKit медиапоток, но проверять оркестрацию: комнаты/токены/вебхуки)
- Любой новый gRPC/Connect метод, который дергает клиент напрямую

E2E-тест живёт рядом с фичей (`services/<name>/e2e/`), гоняется только в Docker, никогда на голом хосте.

## Инструментарий
- Go: `testcontainers-go` для integration, отдельный `docker-compose.e2e.yml` для полного стека в e2e.
- Web: Playwright — против поднятого через Docker стека (gateway + fake/реальные сервисы).
- Мобилка/десктоп (SwiftUI): XCUITest — против того же Docker-стека через настраиваемый base URL.

## CI
- Unit — на каждый PR, быстро.
- Integration/E2E — на каждый PR перед мержем в основную ветку (не на каждый коммит в фиче-ветке, чтобы не тормозить итерацию).
